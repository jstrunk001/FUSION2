Architecture & Algorithms

Processing LiDAR Points as Sparse Rasters on CUDA Cores

Target System: FUSION2 Native Engine Core Concept: Spatial Quantization, Morton Indexing, & Sparse Column GPU Reduction Date: October 2026

1. Executive Summary

Yes, treating LiDAR points as a sparse raster (or 2.5D column-sparse grid) is one of the most effective and proven patterns in modern GPU computing.

Raw LiDAR point clouds are unstructured $(X, Y, Z)$ collections, but forestry metrics (e.g. gridmetrics) are inherently gridded spatial reductions. By mapping point coordinates to discrete raster cell keys on the GPU, points are converted into structured sparse 2D matrices or Morton-ordered streams. This allows CUDA cores to operate with maximum coalesced memory throughput and zero CPU sorting overhead.

The Fundamental Paradigm Shift

Instead of treating LiDAR as an unstructured list of points that must be scattered into millions of dynamic CPU vectors (std::vector<float>), LiDAR points are mapped into linearized 2D raster keys on the GPU. A single GPU Radix Sort or Atomic Spatial Binning groups tens of millions of points in under 10 milliseconds.

2. Why Unstructured LiDAR Is Hard on CPUs (and Natural on GPUs)

In FUSION2's current CPU implementation (gridmetrics.cpp):

  • Points arrive in random scanline order from LAS/LAZ files.
  • For every point, the CPU calculates row and col, looks up grid[row * cols + col], and appends the point to a dynamically-sized heap vector (elevations.push_back(z)).
  • This creates random pointer chasing, cache thrashing, and memory fragmentation across millions of heap vectors.
  • Then, the CPU must sort every cell's vector independently ($O(N \log N)$) across all cells.

3. Three Architectural Patterns for Sparse LiDAR on CUDA Cores

Pattern 1: Linearized Raster Key Sorting (GPU Radix Sort)

Every point calculates its 1D raster index cell_id = row * cols + col (or a 2D Morton Z-order code). Using NVIDIA's ultra-fast cub::DeviceRadixSort, 50 million points are sorted by cell ID in under 8 milliseconds. Once sorted, all points belonging to a cell sit in contiguous memory, ready for segmented histogram reduction.

Pattern 2: Lock-Free Atomic Spatial Bins (Head-Index List)

A 2D raster array of integer heads (int head[cols * rows]) is allocated on device RAM. As points stream through CUDA threads in parallel, each thread performs an atomic exchange: int old = atomicExch(&head[cell_id], pt_idx), linking points into per-cell chains in 1 to 2 milliseconds without sorting.

Pattern 3: Direct 2.5D Sparse Raster Accumulator

For tools like canopymodel, points are mapped directly to a fine 2D raster (e.g., 1 ft or 0.5 m). Each CUDA thread executes atomicMax() on the raster cell in device memory. A 100-million point cloud is rasterized into a clean Canopy Height Model in less than 5 milliseconds.

4. Mathematical Workflow: From Sparse Points to Zonal Metrics

The End-to-End CUDA Sparse Raster Pipeline

1. Stream LAS/LAZ points directly to GPU device buffer ($X, Y, Z, \text{int}, \text{rgb}$).
2. Compute 2D Raster Cell Key: cell_id = floor((x - xmin)/res) + floor((ymax - y)/res) * cols.
3. Parallel Radix Sort (CUB): Keys and point indices are sorted into contiguous spatial clusters.
4. Segmented Shared-Memory CDF Histogram: One CUDA threadblock per active raster cell accumulates point heights/intensities into the 2,048-bin shared-memory histogram and extracts all 21 metrics in registers.
5. Write Directly to GDAL Raster / SQLite Buffer.

CUDA Kernel Structure for Sparse Cell Reduction

__global__ void sparse_cell_histogram_kernel(
    const int* __restrict__ cell_offsets,     // Start offset of each active cell
    const int* __restrict__ cell_point_counts,// Number of points in each active cell
    const float* __restrict__ d_z,            // Point elevations
    const uint16_t* __restrict__ d_intensity, // Point intensities
    float* __restrict__ d_out_metrics,        // 21-band output metrics raster
    int num_active_cells
) {
    int cell_idx = blockIdx.x;
    if (cell_idx >= num_active_cells) return;

    __shared__ int s_hist[2048];
    int tid = threadIdx.x;

    // 1. Zero histogram bins cooperatively
    for (int b = tid; b < 2048; b += blockDim.x) {
        s_hist[b] = 0;
    }
    __syncthreads();

    // 2. Stream through all points belonging to THIS sparse cell
    int start = cell_offsets[cell_idx];
    int count = cell_point_counts[cell_idx];

    for (int i = tid; i < count; i += blockDim.x) {
        float z = d_z[start + i];
        int bin = clamp((int)floor((z - htbreak) / bin_width), 0, 2047);
        atomicAdd(&s_hist[bin], 1);
    }
    __syncthreads();

    // 3. Single-pass cumulative scan to extract percentiles & mode directly into registers
    if (tid == 0) {
        ExtractPercentilesAndStats(s_hist, d_out_metrics, cell_idx);
    }
}

6. Synergy with the Julia Raster Project

Treating LiDAR as a sparse raster completely unifies the Point Cloud Pipeline (FUSION2) with the Raster Pipeline (2026_RasterMetrics/julia):

  • Identical GPU Kernel Downstream: Once LiDAR points are binned into cell keys on the GPU, the reduction kernel (2,048-bin shared-memory CDF histogram) is literally identical to the one already validated in Julia!
  • Multi-Modal Ingestion: Whether the input is a 100M-pixel NAIP3D photogrammetric DSM GeoTIFF or a 50M-point USGS LiDAR LAS/LAZ file, both reduce to the same sparse raster representation in GPU memory, producing identical FUSION-standard outputs.

7. Summary & Recommendations for FUSION2

  1. Adopt Linearized Cell Indexing: In FUSION2's data structures, represent spatial location using a compact uint32_t cell_key instead of dynamic vector pointers.
  2. Leverage NVIDIA CUB: CUB is a standard header-only library included with CUDA that provides optimal GPU radix sorting and segmented reductions with zero tuning.
  3. Direct CHM Rasterization: For canopymodel.exe, a sparse 2D raster with atomicMax() provides instantaneous Canopy Height Models from raw LiDAR points.
